# Azure deployment plan

## Recommended hosting

Use **Azure Static Web Apps** for this project. Flip Eight is a static browser application: it does not need a server, database, model endpoint, or paid API. Static Web Apps can host the HTML, CSS and JavaScript files over HTTPS and can be connected to a GitHub repository.

## Architecture

1. The browser downloads `index.html`, `styles.css`, and the ES modules in `src/` from Azure Static Web Apps.
2. The game runs in the user's browser. Card state is held in memory while a round is active.
3. Completed round summaries are saved to browser `localStorage`. No personal profile or remote database is used.
4. GitHub Actions runs the Node.js unit tests on pushes, pull requests, and manual workflow dispatch.
5. A production deployment can be linked to the repository using the Static Web Apps GitHub integration. Configure the app location as `/`, API location as empty, and output location as empty for a static site with no build step.

## Deployment steps

1. Push the project to a GitHub repository.
2. In the Azure portal, create a Static Web App and choose the repository and deployment branch.
3. Select the custom build preset or configure the workflow with app location `/`, API location empty, and output location empty. There is no framework build command.
4. Review the generated workflow and ensure its deployment job runs only for the intended branch. GitHub Actions needs the deployment token/credential generated by Azure; do not paste it into source files or commit it.
5. Wait for the workflow to finish and open the generated HTTPS URL. Test a round, restart while cards are waiting to flip back, and verify that history remains on the same browser.

## Identity and secrets

The game does not collect or transmit credentials and has no application secrets. Let Azure's GitHub integration configure the deployment credential in repository Actions secrets. Prefer federated identity/OIDC where the selected Azure deployment setup supports it. Never commit access tokens, `.env` files containing secrets, or personal data. The local `.env.example` is not needed because the application has no environment variables.

## Monitoring and support

Use the Static Web Apps deployment history and GitHub Actions logs to troubleshoot failed deployments. Browser issues can be reproduced using the included test cases and the browser developer console. If the app later adds an API, use Azure App Service or Azure Functions for the API, managed identity for Azure resource access, and Application Insights for server-side telemetry; none of these are necessary for this prototype.

## Cost and limitations

The prototype is designed for the Static Web Apps Free plan where available; check current Azure pricing and regional availability before deployment. The game has no server-side account sync: history is local to one browser and can be cleared by the user. A browser's storage restrictions or private browsing mode may prevent history from persisting. This is a deliberate scope choice for a small assessment prototype.
